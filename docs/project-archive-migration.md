# 胶卷项目归档、迁移与恢复

## 分支与状态

本功能在 `refactor/v0.7-architecture` 分支开发，不改变 `main`，不发布正式版本。

项目归档合同版本为 `1`，项目数据库结构合同版本为 `6`。

## 项目归档格式

归档扩展名为：

```text
.psszproj
```

归档本质为带版本清单的 ZIP 容器，包含：

- `manifest.json`：项目名称、公共信息、图片顺序、当前图片、每张图片完整状态、输出预设和原图指纹。
- `originals/`：用户选择包含原图时保存原始文件；原图使用不重新编码的方式写入。

清单写入：

- 归档格式标识；
- 归档结构版本；
- UTC 创建时间；
- 图片顺序；
- 调色、分析、裁切、旋转、几何、RAW 和输出设置；
- 画面编号；
- 已导出状态；
- 原始路径、文件名、字节数、修改时间和 SHA-256；
- 最后使用的输出预设。

归档写入临时文件，完成后再原子替换目标文件。失败时不会留下伪装成完整归档的半成品。

## 两种归档模式

### 仅保存项目参数

归档只包含项目状态和原图指纹，文件较小。适合：

- 同一电脑备份项目参数；
- 原图由 NAS 或移动硬盘单独管理；
- 另一台电脑已有同一批原图。

导入后原路径无效时，使用“重新定位原图”搜索新的根目录。

### 项目参数与原图一起保存

仍可读取的原图按原始字节写入归档。适合：

- 将整卷交给另一台电脑继续处理；
- 长期归档；
- 原图路径将发生变化；
- 不依赖原 NAS 或外置硬盘。

导入时必须选择原图解压目录。程序在项目名目录下恢复原图，并自动处理文件名冲突。

## 导入规则

- 每次导入都创建一个独立的新项目，不覆盖现有项目。
- 项目重名时自动追加“导入”标记和序号。
- 输出预设重名时也创建独立名称，不修改现有预设。
- 归档包含原图时先安全校验每个内部路径，禁止绝对路径和 `..` 路径穿越。
- 图片状态在原图路径确定后写入数据库。
- 导入失败时删除未完成项目并恢复原活动项目。

## 原图重新定位

重新定位会递归扫描用户选择的目录，并依次使用：

1. 原始文件名；
2. 文件字节数；
3. 存在多个候选时的 SHA-256；

进行匹配。

结果分为：

- 已重新定位；
- 没有找到；
- 存在多个候选。

只有唯一匹配的文件会自动更新。项目图片顺序、每张图片参数、画面编号和导出记录保持不变。

## 项目完整性检查

普通检查包含：

- 原图是否存在；
- 文件大小是否变化；
- 画面编号是否为空；
- 画面编号是否重复；
- 项目引用的输出预设是否存在。

深度检查会额外重新计算 SHA-256。大尺寸 RAW 文件较多时，深度检查需要更长时间。

检查只读取文件，不修改原图。

## 全数据库备份与恢复

数据库备份使用 SQLite 在线备份 API，而不是直接复制正在写入的数据库文件，因此会同时包含 WAL 中已经提交的数据。

备份流程：

1. 保存尚未落盘的当前项目状态；
2. SQLite 在线备份到临时数据库；
3. 执行 `PRAGMA quick_check`；
4. 检查必要的数据表；
5. 关闭所有 SQLite 文件句柄；
6. 原子替换最终备份文件。

恢复流程：

1. 以只读方式检查备份完整性；
2. 备份到恢复临时文件；
3. 再次执行完整性检查；
4. 关闭源和目标连接；
5. 清理旧 WAL/SHM；
6. 原子替换当前数据库；
7. 重新初始化数据库并恢复活动项目。

该顺序兼容 Windows 对已打开文件不能替换的限制。

## 界面入口

左侧“胶卷项目”区域新增：

```text
归档与迁移工具
```

工具窗口包含：

- 导出当前项目；
- 导入项目归档；
- 重新定位原图；
- 检查项目完整性；
- 备份全部项目；
- 恢复全部项目。

耗时操作在后台线程执行。运行期间相关按钮会禁用，窗口不能被误关闭，完成或失败后再回到可操作状态。

## 数据安全约束

- 不覆盖原图；
- 不在归档过程中重新编码原图；
- 不静默覆盖已有项目、预设或解压文件；
- 不从不安全归档路径解压；
- 不使用仍被 SQLite 连接占用的文件执行替换；
- 项目导入失败时不保留半完成记录；
- 数据库恢复前必须通过结构与完整性检查。
