# PS-Sezhao 架构整理计划

## 目标

本轮开发在独立分支进行，不改变当前正式版本。核心目标是减少启动阶段的隐式修改，建立稳定模块边界，并为胶卷项目、后台处理和版本化数据保存准备基础设施。

## 当前进展

- 已完成统一、幂等的应用组装入口。
- 已建立 `core`、`services`、`ui`、`storage` 四个稳定目录。
- 已将图片与文件夹扫描迁移到导入服务。
- 已增加真实 Tk 窗口启动测试。
- 已增加拖放运行时安全降级，动态库不兼容时保留普通窗口。
- 已接入版本化 SQLite 工作状态保存。
- 已支持自动保存图片顺序、当前图片、编辑参数、分析结果、裁切和旋转。
- 已支持无启动文件时恢复上次仍存在的图片与对应编辑状态。
- 已建立轻量缩略图、高质量编辑代理和全分辨率输出三级读取流程。
- 已限制编辑代理为最多 4 张并同时设置内存上限。
- 已支持当前代理完成后自动预解码下一张图片。

## 第一阶段：启动与模块边界

- 将所有引擎、运行时和界面组装集中到一个幂等入口。
- `main.py` 只负责调用统一启动函数，不再直接排列多个界面修改模块。
- 建立 `core`、`services`、`ui`、`storage` 四个稳定目录。
- 将图片与文件夹扫描逻辑从界面模块移到导入服务。
- 将预览、保存和中性色计算的运行时绑定集中到处理服务。
- 增加真实 Tk 窗口创建测试，防止控件引用失效、重复创建和启动崩溃。

## 第二阶段：本地项目数据

- 使用 SQLite 保存图片路径、编辑参数、分析结果、裁切、旋转和更新时间。
- 保存当前图片列表顺序与当前选中的图片。
- 参数改变后延迟写入，连续拖动滑块时避免频繁打开数据库。
- 关闭程序前立即写入尚未落盘的修改。
- 启动时忽略已经移动或删除的原图，只恢复仍然存在的文件。
- 为处理算法、RAW 解码和数据库结构分别记录版本号。
- 为旧数据提供明确迁移流程。
- 原图只保存路径，不复制、不覆盖。

## 第三阶段：导入、预览与导出边界

- 导入或切换图片时先读取轻量缩略图，不立即完整解码 RAW。
- 当前图片使用最长边受控的高质量编辑代理进行分析、校色、裁切和显示。
- 编辑代理使用条目数与总内存双重限制，当前上限为 4 张和 256 MiB。
- 当前图片代理生成后，自动预解码列表中的下一张图片。
- 缩略图与代理均根据文件大小、修改时间和 RAW 设置生成缓存键。
- RAW 设置改变并重新解码时，清除该文件原有缩略图与代理。
- 保存当前、批量导出和 Lightroom 高精度处理时才读取全分辨率原图。
- 后台导出继续保留进度与失败信息；取消机制在后续输出队列阶段接入。

## 第四阶段：几何与批量设置

- 自动范围检测返回可信度，失败时保留安全默认框。
- 增加拉直、翻转和四角透视校正。
- 同一固定机位的几何设置可批量应用。
- 多图同步改为模块选择，可分别复制基底、调色、风格、RAW、几何和输出设置。
- 批量修改在一个事务中完成，失败时不留下部分更新。

## 第五阶段：完整输出

- 支持输出格式、位深、色彩空间、尺寸、锐化和 JPEG 质量。
- 支持文件名模板、自动序号和重名策略。
- 可选写入胶卷型号、相机、日期和画面编号。
- 支持整卷导出和接触印样。
- 建立预览、独立版导出、Photoshop 输出和 Lightroom 高精度输出的一致性测试。

## 开发约束

- 正式版本在分支验证完成前不合并。
- 新功能优先进入稳定模块，不继续扩大启动入口。
- 界面创建必须有启动测试覆盖。
- 处理参数和数据结构发生变化时必须提升对应合同版本。
- 预览和最终导出必须使用同一数学定义。
