# PS-Sezhao 架构整理计划

## 目标

本轮开发在独立分支进行，不改变当前正式版本。核心目标是减少启动阶段的隐式修改，建立稳定模块边界，并为胶卷项目、后台处理和版本化数据保存准备基础设施。

## 当前进展

- 已完成统一、幂等的应用组装入口。
- 已建立 `core`、`services`、`ui`、`storage` 四个稳定目录。
- 已将图片与文件夹扫描迁移到导入服务。
- 已增加真实 Tk 窗口启动测试。
- 已增加拖放运行时安全降级，动态库不兼容时保留普通窗口。
- 已接入版本化 SQLite 工作状态保存。
- 已支持自动保存图片顺序、当前图片、编辑参数、分析结果、裁切和旋转。
- 已支持无启动文件时恢复上次仍存在的图片与对应编辑状态。
- 已建立轻量缩略图、高质量编辑代理和全分辨率输出三级读取流程。
- 已限制编辑代理为最多 4 张并同时设置内存上限。
- 已支持当前代理完成后自动预解码下一张图片。
- 已建立单线程后台输出队列，界面不再直接承担全分辨率批处理。
- 已支持逐张与分块进度、协作式取消、失败隔离和原子文件写入。
- 已建立统一几何核心，支持拉直、水平翻转、垂直翻转和四角透视。
- 已增加自动范围检测可信度，低可信度时保留完整画面。
- 已将多图同步改为按模块选择，并提供固定机位几何快捷选择。
- 已将几何、RAW 和输出设置纳入每张图片的自动保存与恢复。
- 已建立完整输出合同，统一独立版、批量队列和 Lightroom 高精度任务。
- 已支持 TIFF/JPEG/PNG、位深、ICC、尺寸、缩放算法、最终锐化和 JPEG 质量。
- 已支持文件名模板、自动序号、覆盖、跳过和重名报错策略。
- 已支持写入胶卷、胶卷型号、相机、日期、画面编号和备注。
- 已支持从选中图片或整卷生成接触印样。
- 已支持在同一数据库中保存多个相互独立的胶卷项目。
- 已保存每个项目的图片顺序、当前图片、每张图片参数和最后输出状态。
- 已支持项目级公共信息、画面编号自动生成和按列表顺序重新编号。
- 已支持输出预设保存、应用到当前或选中图片以及跨会话恢复。
- 已增加整卷总数、已分析、已编辑和已导出进度统计。

## 第一阶段：启动与模块边界

- 将所有引擎、运行时和界面组装集中到一个幂等入口。
- `main.py` 只负责调用统一启动函数，不再直接排列多个界面修改模块。
- 建立 `core`、`services`、`ui`、`storage` 四个稳定目录。
- 将图片与文件夹扫描逻辑从界面模块移到导入服务。
- 将预览、保存和中性色计算的运行时绑定集中到处理服务。
- 增加真实 Tk 窗口创建测试，防止控件引用失效、重复创建和启动崩溃。

## 第二阶段：本地项目数据

- 使用 SQLite 保存图片路径、编辑参数、分析结果、裁切、旋转和更新时间。
- 保存当前图片列表顺序与当前选中的图片。
- 参数改变后延迟写入，连续拖动滑块时避免频繁打开数据库。
- 关闭程序前立即写入尚未落盘的修改。
- 启动时忽略已经移动或删除的原图，只恢复仍然存在的文件。
- 为处理算法、RAW 解码和数据库结构分别记录版本号。
- 为旧数据提供明确迁移流程。
- 原图只保存路径，不复制、不覆盖。

## 第三阶段：导入、预览与导出边界

### 导入与编辑代理

- 导入或切换图片时先读取轻量缩略图，不立即完整解码 RAW。
- 当前图片使用最长边受控的高质量编辑代理进行分析、校色、裁切和显示。
- 编辑代理使用条目数与总内存双重限制，当前上限为 4 张和 256 MiB。
- 当前图片代理生成后，自动预解码列表中的下一张图片。
- 缩略图与代理均根据文件大小、修改时间和 RAW 设置生成缓存键。
- RAW 设置改变并重新解码时，清除该文件原有缩略图与代理。
- 保存当前、批量导出和 Lightroom 高精度处理时才读取全分辨率原图。

### 后台输出队列

- 保存当前、导出选中和导出全部共用一个顺序输出队列。
- 全分辨率读取、旋转、几何、裁切、正片计算和文件写入均在后台线程执行。
- 界面显示当前图片、处理阶段、单张进度与整批进度。
- 用户可以取消输出；当前 RAW 解码结束或当前处理分块结束后停止。
- 单张图片失败时记录错误并继续处理后续图片。
- 批量结束后集中显示失败摘要，不为每一张失败弹出阻塞窗口。
- 文件先写入同目录临时文件，成功后原子替换目标，避免留下半成品。
- 批量输出遇到同名文件或相同文件名时自动追加序号，不覆盖已有文件。
- 关闭程序时请求取消仍在执行或排队的输出任务。

## 第四阶段：几何与批量设置

- 自动范围检测返回可信度，低可信度时保留安全完整画面。
- 拉直、水平翻转、垂直翻转和四角透视使用统一浮点几何核心。
- 预览代理、单张保存、批量导出和 Lightroom 高精度任务使用同一几何顺序。
- 四角透视按左上、右上、右下、左下的顺序直接在预览中选择。
- 同一固定机位的旋转、拉直、翻转、透视和裁切可一次应用到多张图片。
- 多图同步可分别复制基底、风格、明暗、颜色、RAW、几何、裁切和输出设置。
- 批量修改先生成全部目标状态，确认无错误后一次写入，再由 SQLite 事务保存。

## 第五阶段：完整输出

### 画质与色彩

- 输出格式支持 16 位 TIFF、8 位 TIFF、JPEG 和 PNG。
- JPEG 质量可设置为 1–100，TIFF 和 PNG 使用无损保存。
- 色彩空间支持保留输入 ICC、ProPhoto RGB 和 sRGB。
- RAW 的 ProPhoto 工作数据转换到 sRGB 时使用浮点矩阵转换，不先降为 8 位。
- 输出尺寸支持原始尺寸、最长边、固定宽度、固定高度和百分比。
- 可选择是否允许放大，缩放算法支持 Lanczos、双三次、双线性和最近邻。
- 输出锐化在最终像素尺寸上执行，提供关闭、轻微、标准和较强四档。

### 文件命名与重名处理

- 文件名模板支持原文件名、整卷序号、胶卷名称、胶卷型号、画面编号、相机、日期和风格标记。
- 自动移除 Windows 与 macOS 不允许出现在文件名中的字符。
- 重名时可选择自动编号、覆盖、跳过或报错。
- 同一批任务中的重复名称也会受到保护，不会由后一个任务静默覆盖前一个任务。

### 胶卷信息与元数据

- 每张图片可独立保存胶卷/批次名称、胶卷型号、相机或扫描仪、拍摄日期、画面编号和备注。
- 元数据可写入 TIFF ImageDescription、JPEG EXIF 和 PNG 文本字段。
- 元数据模块可通过多图同步复制到整卷。
- 完整输出设置保存在项目数据库中，重新打开程序后恢复。

### 接触印样

- 可从当前选中图片生成接触印样；只选择一张时默认使用整卷。
- 可设置每行列数、单格尺寸、深浅背景和是否显示文件名。
- 每张缩略图使用自身的旋转、几何、裁切、胶片基底和调色参数。
- 接触印样在后台生成，不阻塞主界面。

### 一致性

- 独立版保存、批量输出和 Lightroom 高精度任务共享同一完整输出合同。
- 输出阶段统一执行：完整正片计算、色彩空间、尺寸、锐化、元数据和文件写入。
- 输出队列仍保留取消、单张失败隔离、原子写入和临时文件清理。
- 自动测试直接读取最终 TIFF、JPEG 和 PNG，验证像素尺寸、位深、ICC、元数据与命名行为。

## 第六阶段：胶卷项目与输出预设

### 多项目管理

- 一个 SQLite 数据库可以保存多个相互独立的胶卷项目。
- 每个项目保存图片顺序、当前图片、每张图片的完整编辑状态和最后输出位置。
- 程序启动时优先恢复上次处于活动状态的胶卷项目。
- 项目列表显示图片数量、已导出数量和最后更新时间。
- 删除项目只删除项目数据，不删除任何原始图片或已经输出的文件。

### 项目公共信息与编号

- 项目级公共信息包括胶卷名称、胶卷型号、相机或扫描仪、日期和备注。
- 画面编号支持前缀、起始值和编号位数。
- 新加入项目的图片自动获得当前顺序对应的画面编号。
- 可按照当前图片列表顺序重新生成全部画面编号。
- 公共信息可以覆盖到整卷，也可以保留某张图片已经单独填写的内容。

### 输出预设

- 当前格式、位深、色彩空间、尺寸、锐化、命名和重名策略可以保存为命名预设。
- 输出预设可以应用到当前图片或左侧选中的多张图片。
- 输出预设不覆盖胶卷名称、胶卷型号、相机、日期、画面编号和备注。
- 项目记录最后使用的输出预设，重新打开项目时继续使用。

### 项目状态

- 左侧项目区域显示整卷总数、已分析、已编辑和已导出数量。
- 导出成功后记录原图、输出路径和导出时间。
- 重新打开项目后继续显示已完成和待处理的进度。
- 项目切换前先保存当前项目，避免跨项目丢失未落盘参数。

## 开发约束

- 正式版本在分支验证完成前不合并。
- 新功能优先进入稳定模块，不继续扩大启动入口。
- 界面创建必须有启动测试覆盖。
- 处理参数和数据结构发生变化时必须提升对应合同版本。
- 预览和最终导出必须使用同一数学定义。
